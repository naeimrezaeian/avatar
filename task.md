Разработку платформы необходимо разделить на три основные части:

1. Веб-интерфейс и клиентская часть.
2. Серверная часть.
3. Модели искусственного интеллекта.

На первом этапе необходимо разработать веб-интерфейс и клиентскую часть платформы.

## 1. Технологии для разработки веб-интерфейса

Для клиентской части предлагается использовать следующие технологии:

* Next.js;
* React;
* TypeScript;
* Tailwind CSS;
* библиотеку компонентов shadcn/ui.

Такой технологический стек позволит создать современный, быстрый, адаптивный и удобный интерфейс, который будет хорошо работать как на компьютерах, так и на мобильных устройствах.

## 2. Основные разделы платформы

В системе необходимо предусмотреть следующие разделы:

* главная страница;
* страница входа;
* страница регистрации;
* восстановление пароля;
* личный кабинет пользователя;
* управление цифровыми аватарами;
* управление голосами;
* управление проектами;
* рабочее пространство для создания видео;
* библиотека созданных видео;
* библиотека изображений, аудиофайлов и других материалов;
* история генераций;
* уведомления;
* настройки профиля;
* настройки системы;
* управление тарифом и кредитами;
* панель администратора;
* управление пользователями;
* управление ролями и правами доступа;
* просмотр статистики использования платформы;
* журнал системных действий и ошибок.

## 3. Регистрация и авторизация

Необходимо разработать современные страницы входа и регистрации.

Пользователь должен иметь возможность:

* зарегистрироваться с помощью электронной почты;
* подтвердить адрес электронной почты;
* войти в систему;
* восстановить забытый пароль;
* изменить пароль в настройках профиля;
* выйти со всех активных устройств;
* просматривать активные сессии.

Интерфейс страниц входа и регистрации должен быть современным, привлекательным и соответствовать общему стилю платформы.

## 4. Управление пользователями

Администратор должен иметь возможность:

* добавлять новых пользователей;
* редактировать данные пользователей;
* удалять и блокировать пользователей;
* назначать роли;
* изменять права доступа;
* просматривать активность пользователей;
* просматривать количество использованных кредитов;
* добавлять или уменьшать доступное время генерации видео;
* просматривать историю проектов и генераций пользователя.

Для каждого пользователя необходимо хранить:

* имя и фамилию;
* адрес электронной почты;
* фотографию профиля;
* роль;
* статус учётной записи;
* дату регистрации;
* дату последнего входа;
* доступное количество кредитов;
* количество использованных минут генерации видео.

## 5. Система кредитов

Каждый пользователь должен иметь определённое количество кредитов для создания видео.

Кредиты измеряются в доступных минутах генерации видео. Количество минут определяет администратор или выбранный тарифный план.

Пользователь должен видеть:

* общее количество доступных минут;
* количество использованных минут;
* оставшийся баланс;
* историю списания и начисления кредитов;
* примерную стоимость генерации перед её запуском.

Перед началом генерации система должна проверять, достаточно ли у пользователя кредитов.

Если кредитов недостаточно, пользователь должен получить соответствующее уведомление.

Администратор должен иметь возможность:

* вручную начислять кредиты;
* списывать кредиты;
* устанавливать срок действия кредитов;
* создавать тарифные планы;
* устанавливать ограничения для разных пользователей;
* просматривать подробную историю использования кредитов.

## 6. Управление цифровыми аватарами

Пользователь должен иметь возможность создавать несколько цифровых аватаров.

Для каждого аватара пользователь может:

* указать название;
* загрузить фотографию;
* загрузить несколько изображений;
* выбрать основное изображение;
* загрузить образец голоса;
* записать голос непосредственно на платформе;
* выбрать язык и стиль речи;
* просмотреть тестовое видео;
* изменить параметры аватара;
* удалить или архивировать аватара.

В системе должен отображаться статус подготовки аватара:

* материалы загружены;
* выполняется обработка;
* аватар готов;
* произошла ошибка.

## 7. Управление проектами

Пользователь должен иметь возможность создавать несколько проектов.

Каждый проект представляет собой отдельное рабочее пространство, в котором хранятся:

* выбранный цифровой аватар;
* сценарий;
* промпты для генерации видео;
* созданные сцены;
* изображения;
* аудиофайлы;
* фоновая музыка;
* настройки проекта;
* история изменений;
* готовые версии видео.

Пользователь должен иметь возможность:

* создать новый проект;
* переименовать проект;
* создать копию проекта;
* архивировать проект;
* удалить проект;
* восстановить удалённый проект;
* просмотреть дату последнего изменения;
* сохранить проект как шаблон.

Все изменения в проекте должны сохраняться автоматически.

## 8. Рабочее пространство для создания видео

Рабочее пространство должно быть похоже на современные видеоредакторы, например CapCut, но при этом оставаться простым и удобным для обычного пользователя.

В рабочем пространстве пользователь должен иметь возможность:

* выбрать цифрового аватара;
* добавить текст для озвучивания;
* выбрать голос;
* настроить скорость, интонацию и громкость речи;
* написать промпт для генерации видео;
* выбрать формат и соотношение сторон видео;
* добавить изображение;
* добавить фон;
* добавить собственный видеоролик;
* добавить текстовые надписи;
* добавить логотип;
* добавить субтитры;
* добавить переходы между сценами;
* добавить визуальные эффекты;
* изменить положение и размер аватара;
* переместить аватара в левую, правую или центральную часть кадра;
* изменить масштаб аватара;
* скрыть аватара в отдельных сценах;
* заменить фон;
* добавить несколько сцен;
* менять порядок сцен;
* предварительно просматривать результат.

## 9. Временная шкала

В нижней части редактора необходимо реализовать удобную временную шкалу.

На временной шкале должны быть отдельные дорожки для:

* обрезать видео и аудио;
* копировать элементы;
* удалять элементы;
* менять порядок сцен;
* регулировать громкость;

* увеличивать и уменьшать масштаб временной шкалы;
* отменять и повторять действия.

## 10. Экспорт готового видео

После завершения работы пользователь должен иметь возможность экспортировать готовое видео.

При экспорте необходимо предоставить следующие настройки:

* разрешение видео;
* качество видео;
* частота кадров;
* формат файла;
* соотношение сторон;
* наличие субтитров;
* наличие водяного знака;
* качество звука.

Необходимо поддержать основные форматы:

* горизонтальное видео 16:9;
* вертикальное видео 9:16;
* квадратное видео 1:1;
* формат для социальных сетей;
* формат для презентаций и обучающих материалов.

Пользователь должен видеть статус экспорта:

* ожидает обработки;
* выполняется генерация;
* выполняется сборка проекта;
* выполняется экспорт;
* видео готово;
* произошла ошибка.

После завершения пользователь должен иметь возможность:

* просмотреть видео;
* скачать видео;
* создать новую версию;
* скопировать проект;
* поделиться ссылкой на видео;
* удалить готовое видео.
